# RC63 · 설정 / 전투 / 서사 / 자산 전수 점검

## 결과 요약

RC62 정본 위에 RC63 안정화 수정 1건과 회귀 테스트 보강 1건을 적용했다. STORY·HELL·DREAM 세 모드의 선택·새 게임 시작·저장값이 실제 플레이 상태에서 일치하는지 확인했으며, 맵·서사·전투·스킬/이미지 회귀는 기존 정본 규칙을 유지했다.

## 이번에 고친 문제

1. 파티/난이도 창의 모드 선택이 새 게임에 전달되지 않아 HELL 또는 DREAM을 선택해도 React 시작 상태의 기본값 STORY로 덮일 수 있었다. 시작 화면과 파티 창이 같은 모드 값을 사용하도록 동기화하고, 서비스 초기화 전에도 STORY/HELL/DREAM 선택값을 보존하도록 수정했다. 실제 새 게임 진입 브라우저 검사에서 세 모드의 상태, 저장값, 서사 표시 여부, Dream 각성 상태와 HELL 규칙을 확인했다.
2. RC54 시각 브라우저 테스트가 RC54 패치 뒤의 RC55 이후 코드까지 함께 실행해 테스트에 준비되지 않은 `cult03` 때문에 실패했다. 테스트 실행 범위를 RC54 코드로 한정했다. 이는 게임 런타임 결함이 아니라 테스트 fixture의 오래된 경계 오류였다.
3. RC50·RC54·RC55·RC56·RC59의 캐시 검사들이 `v=36201`에 고정돼 있었다. 이후에도 유지되는 “현재 키가 RC63 이상” 검사로 바꿨다.

## 조사 범위와 보존 기준

- 전체 모드: STORY / HELL / DREAM. HELL의 무대 대사 제외, DREAM의 각성·거울·기억 효과, STORY의 전후 독백을 기존 규칙대로 보존했다.
- 시작 설정: 게임 모드, 전투 조작 세 단계, 모바일 터치 옵션, 효과음, 영웅 8명 선택, 선택 실패 후 재접속 경로.
- 서사/맵: 업로드 독백 정본 61개 레코드(전투 55 + 쉼터 6), 환자기록 보관소 62개 항목(프롤로그 포함), 포털 순서, 구역·보스 연결, 맵/적 이미지 경로.
- 전투: 입력·자동전투, 근접/원거리/레이저 피격, 모바일 성능 제한, 모드별 난이도, 27개 보스 개념, 85개 시그니처 공격과 프롤로그 공격명, 38개 중간보스 맵 짝 편성.
- 이미지/스킬: 저장소 내 PNG/WebP/JPEG/GIF 2,124개를 실제 디코딩 검사했고 오류 0건. 소스 내 이미지·오디오·스타일·스크립트 자산 참조 7,414건 누락 0건. 적 스프라이트 259/259, 전투맵 이미지 55/55의 정적 연결을 재검사했다.

## 동방 탄막 게임에서 가져온 원칙

공식 ZUN 소개문은 게임 시스템·이야기·탄막이 연결되는 점을 설명한다. 이를 HAPIL에서는 이미 구축된 보스별 고유 공격명, 예고 배너, 실제 발사·회복 타이밍, 안전 통로와 패턴 변주로 유지했다. 이번 점검에서는 탄 수나 피해량을 임의로 올리지 않고, 모드 선택이 실제 전투 규칙에 도달하도록 고쳤다. 새 이미지나 추가 탄환은 누락·부적합 증거가 없어 만들지 않았다.

참고: [동방Project 공식 뉴스 · 東方虹龍洞 소개](https://touhou-project.news/news/3368/)

## 검증 기록

- 전체 Node smoke 및 정본 감사: 통과. 이동/탄환 충돌, 스킬/레이저 피해, 보스 패턴·명명, 회복/면역 피드백, 독백 분할, 사망 체크포인트, 중간보스 짝, 55개 맵과 259개 적 스프라이트 경로를 포함.
- 브라우저: RC51 서사/사몽 화면, RC52 플레이어블 8명 전원 시작, RC54 맵/투사체 대체 자산, RC61 설정·실패 복구, RC62 모바일 보스 패턴 배너, RC63 세 모드 및 보관소 검사 통과.
- 화면 크기: 1280×900, 390×844, 360×740, 844×390에서 112개 서사 카드 레이아웃 통과. 390×844 모바일에서 보스 패턴 배너가 잘리지 않는 것 확인.
- 전체 래스터 파일 디코딩과 자산 경로 검사는 파일 무결성을 확인한다. 이전 RC62의 55개 맵 연락표 시각 점검은 참고했으며, 모든 이미지에 대한 미술적/픽셀 단위 평가는 아니다.
