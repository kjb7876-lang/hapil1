# RC91 — 연속 레이저와 사몽 각성

기준: GitHub main의 RC90 `f39f82b740b1aa09773cfd110dda563b322ba9ff`.
RC86–RC90의 서사·코스믹·부속 전투와 저장 복원 수정은 기준 코드에 포함되어 있다.
이 패치는 RC91 코드와 영웅별 각성 그림을 함께 추가한다. 아직 업로드하지 않았다.

## 전투 규칙

| 항목 | 적용된 동작 |
| --- | --- |
| 곡선·복합 레이저 | 보라검천사 계열의 밝은 중심광과 소유자 색 외곽광으로 한 경로를 연속 렌더링한다. 구간마다 이미지 끝을 반복하지 않는다. 둥근 연결부를 쓰며 충돌 샘플도 같은 선분·폭을 읽는다. |
| 굵기 | 복합 경로의 공통 반폭을 기존 대비 1.18배로 확대한다. 이미 전장의 99%를 쓰는 특수 패턴의 범위 상한은 유지한다. 일반 단일 직선은 보스별 원래 그림을 유지한다. |
| 스토리 최종전 | 교주 1차 처단 이후의 서사 흑백 결전은 STORY에 한정한다. 각성 단계에서 실제 플레이 영웅과 선택 참조를 환도로 고정한다. 기존 독백과 최종 처단 진행을 유지한다. |
| 사몽 패시브 | 사몽모드에서 치명타로 HP가 0 이하가 되면 HP 50%로 한 번 부활한다. 발동 즉시 7초 각성과 77초 재사용 대기시간이 시작된다. 대기시간이 끝난 뒤 다시 발동할 수 있다. |
| 각성 버프 | 공격 위력 ×5, 이동속도 ×1.7, 영웅 전투 시계 ×2.2, 받는 최종 피해 ×0.12. 부활 직후 0.6초 동안 후속 타격을 막는다. 기존 스토리 각성의 시간 정지·느려짐·잔상을 재사용한다. |
| 각성 표시 | 「死夢覺醒」과 해당 영웅의 새 RGBA 그림을 표시한다. PC는 전장 오른쪽, 모바일은 화면 오른쪽에 표시해 확대된 캔버스 밖으로 잘리지 않게 한다. 전장과 각성 그림은 흑백이다. |
| 모드 | STORY / DREAM(화면 이름: 사몽) 두 가지. HELL 버튼·선택지를 제거하고 옛 HELL 선택과 저장은 STORY로 옮긴다. 옛 헬 전용 강화·거울 규칙은 실행하지 않는다. |
| 사몽 해금 | 스토리 최종 독백을 마치고 엔딩을 확정하거나 실제 설정의 777 코드를 승인해야 한다. 저장에는 해금 여부도 남긴다. 단순한 옛 DREAM 선택값만으로 해금하지 않는다. |
| 사몽 적 | 같은 스토리 기준의 최대 HP, 공격력, 방어력, 속도 및 공격 빈도를 두 배로 적용한다. 일반 적·중간보스·보스·적 소환체를 포함한다. 아군·보존 대상은 제외한다. 실제 이동·탄막 이동·최종 피격 피해 경로에도 적용한다. |
| 공격 예고 | 새 기본값은 끔. 기존의 명시적 사용자 설정은 유지하며 설정에서 다시 켤 수 있다. 표시만 끄고 예약된 공격·탄막 발사·피해 시점은 보존한다. |

각성 7초와 재사용 77초는 느려진 세계 시간과 분리된 실제 진행 시간으로 계산한다.
메뉴·독백·숨겨진 탭·연결 대기에서는 소모하지 않는다. 저장·불러오기에서 남은 시간을 복원한다.
느린 프레임도 프레임당 0.25초로 잘라 각성이 늘어나는 문제가 없도록 처리했다.

적의 배율은 기준값과 적용 배율을 저장해 프레임마다 중첩되지 않는다.
저장 직전에 새 소환체까지 배율을 적용하고, 실제 최종 복원 순서 뒤에도 HP와 최대 HP를 되돌려 재로드 시 두 배가 다시 곱해지는 문제를 막았다.

## 영웅별 새 그림

`assets/rc91/awakening/`의 환도·서하·네온·미카엘라·라우렌·헌터·악몽검사·거너 그림 8종.
각 영웅의 기존 모습과 무기를 참고해 별도로 생성했으며, 스프라이트 프레임으로 교체하지 않고 각성 연출에만 쓴다.
원본 RGBA PNG를 그대로 저장했다. 파일별 SHA256과 투명도·크기 정보는 같은 폴더의 `manifest.json`에 있다.

## 검증과 범위

- 비브라우저 회귀 테스트 48개 통과. 곡선 연결, 실제 부활 순서, 두 모드 해금, 저장, 대기시간, 배율 중첩 방지, 이미지 8종을 포함한다.
- Chromium 브라우저 검증 7종: RC63, RC85, RC86, RC87, RC88, RC90, RC91.
- RC85는 원래 적 체력·공격력에서 첫 전투 처치 → 전투 후 독백을 확인한다. 테스트 영웅 HP만 보충해 진행 문제를 분리한다.
- RC86/87/88은 목사 그림 경로, 여섯 코스믹 소환, 에피소드 진최종전, 부속 파괴·발사된 탄막 유지 등의 회귀를 확인한다.
- RC90과 RC91은 PC·모바일에서 실제 저장 함수와 최종 복원 순서, 부속/소환체 체력 보존을 확인한다.
- RC91은 실제 피격 코어를 통해 8종 영웅 모두 부활·각성 그림 출력을 확인한다. 치명타 테스트에서는 HP와 대기시간을 준비한다. 메뉴 정지, 실제 각성 만료, 흑백 해제, DREAM 최종전 격리, STORY 환도 고정도 확인한다.
- 동일한 네이티브 공격에서 STORY 피해 35, DREAM 피해 70으로 최종 피해 2배를 확인한다.
- 전체 에피소드의 플레이 난이도를 끝까지 수동으로 평가한 것은 아니다. 온라인 협동의 모든 접속 환경을 보장하는 검증도 아니다.

## Windows 적용

`APPLY_HAPIL_RC91_VERIFIED.ps1` 하나로 별도의 새 폴더에 RC90을 복제하고, 그림이 포함된 체크섬 검증 패치를 적용한다.
JavaScript 구문 검사와 비브라우저 48개 테스트를 실행한 뒤 GitHub main으로 일반 push한다.
Windows에서는 Playwright 14개 테스트 파일을 재실행하지 않는다. 브라우저 검증은 이 패치 제작 환경에서 수행했다.

Git이 있어야 한다. Node가 없거나 18 미만이면 공식 배포본의 SHA256을 확인한 뒤 휴대용 Windows Node를 해당 복제 폴더의 `.git/rc91-tools`에 준비한다.
시스템 Node 설치와 관리자 권한은 필요 없다. 기존 작업 폴더를 덮어쓰지 않고 force push하지 않는다.
main이 검증 기준과 다르게 변경되면 적용 또는 업로드를 중단한다. 인증 오류가 나도 작업 폴더는 보존한다.
