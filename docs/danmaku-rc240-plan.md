# RC240 가로 고밀도 탄막 레이어 — 통합 계획

4개 전문가 관점(탄막 패턴 설계, 시각 연출/VFX, 밸런스·가독성, 성능·통합)의 검토를 하나로 묶은 계획입니다. 세부 수치의 근거는 각 관점별 원본 메모에 있고, 아래는 충돌을 조정한 최종 결정입니다.

## 현재 상태 (측정)

- 보스전 적 탄 평균 25~40발, 최대 약 60발. 탄 물결 사이 1~2초 동안 0발인 구간이 있습니다.
- 주력 탄이 큰 그림 스프라이트(뱀처럼 이어진 사슬)라서 "피해야 할 점"이 아니라 지형·생물처럼 읽힙니다.
- 탄에 발광·흰 코어·외곽선이 없어 청록 방에서는 청록 탄이, 용암 맵에서는 주황 탄이 배경에 묻힙니다.
- 원형·나선·커튼 같은 기하 패턴이 없습니다.
- 기존 탄 1발마다 그림 기반 충돌 재생, 10겹 렌더 래퍼, 개수 기반 해상도 하향이 붙어 있어 기존 큐에 탄을 더 넣는 방식은 비용과 상한(56/40) 문제로 막힙니다.

## 핵심 결정: 별도 레이어 RC240

기존 `hostileProjectiles`에 넣지 않고, 새 스크립트 `assets/rc240/danmaku-layer.js`가 자체 탄 풀을 가집니다.

| 결정 | 이유 | 위험과 추정 |
|---|---|---|
| 자체 SoA 풀(PC 1024 / 모바일 384 칸) | 기존 상한·밀도 복제·해상도 하향과 충돌 없음 | 기존 테스트 계약을 깨뜨릴 가능성 낮음(약 10%) |
| 판정은 심장(반경 4.5) 하나만, 탄은 흰 코어 = 판정 | 동방풍 "보이는 코어만 맞는다" 규칙, 고밀도에서도 공정 | 피격이 너무 적어 쉬워질 수 있음(약 30%) → 밀도 옵션으로 조정 |
| 번들 수정 없이 기존 공개 접점만 감싸기 | 런타임 확장 체인(161번) 한 단계만 추가 | 다른 레이어가 전역을 다시 덮을 위험 → 주기적 재설치 확인 |
| `?qa` 주소에서는 기본 꺼짐(`rc240=1`로 켬) | 기존 브라우저 회귀 게이트가 이전과 같은 결과를 내도록 | 없음 |

## 탄막 패턴 (오리지널 8종)

좁고 넓은 가로 전장(약 1026×284 논리 px)에 맞춰, 보스(오른쪽)가 왼쪽으로 쏘는 호(arc), 벽(curtain), 격자, 사인 물결, 감속 후 재조준, 개화(bloom) 패턴을 씁니다. 화면 위쪽으로 새는 360° 원형은 전장 안에서 터지는 개화탄에서만 씁니다.

| 주문 | 계열 | 구성 |
|---|---|---|
| 질투 · 금 간 거울 회랑 | 질투(거울) | 반사되는 쌍부채 → X자 격자, 개화탄, 지연 조준 |
| 탐욕 · 복리 회수 | 탐욕 | 감속해 쌓이는 금화 호, 멈췄다 재조준하는 "이자" 탄, 2갈래 나선 |
| 분노 · 용암 해일 | 분노(발록) | 틈이 움직이는 탄벽, 포물선 불씨, 조준 부채 |
| 집착 · 끊기지 않는 노랫줄 | 집착/색욕 | 5줄 사인 물결 땋기, 장미 개화 |
| 율법 · 봉인 격자 | 율법/교단 | 교차 바늘 격자, 봉인 조준탄 |
| 몽화 · 피어나는 성운 | 기본/우주 | 4~6갈래 반전 나선, 개화탄 |
| 교만 · 추락하는 일곱 왕관 | 루시퍼/우주 | 감속 호, 떨어져 갈라지는 7개 왕관 |
| 탐식 · 되삼키는 식탁 | 탐식 | 되돌아오는 호(두 번 피하기), 조준 부채 |

- 모든 주문에 움직이는 "안전 각" 하나를 두고 방사형 탄은 그 각도 근처를 비웁니다. 탄벽의 틈도 같은 안전선을 따라갑니다.
- 기존 RC129 주문 순환(12초 스토리 / 10초 드림, 체력 구간 1~3)에 맞춰 선언 1초 → 방출 → 마무리, 구간이 바뀌면 탄을 점수 불꽃으로 소거합니다.
- 보스 고유 대형 공격(RC231 major 창), 레이저 시전, 연출 잠금 중에는 새 탄을 쏘지 않습니다.

## 밀도와 속도 (조정 결과)

패턴 전문가는 PC 최대 300~480발, 밸런스 전문가는 110~360발을 제안했습니다. 사용자 목표(이미지 수준의 밀도)를 우선해 **탄을 느리게 하고 개수를 늘리는** 쪽으로 맞췄습니다. 영웅의 화면 세로 이동 속도가 약 124 px/s로 느리기 때문에, 빠른 탄 대신 느린 탄을 많이 까는 것이 공정성과 밀도를 함께 얻는 방법입니다.

| 모드 | PC 최대 (구간 1→3) | 모바일 최대 | 탄 속도 px/s (조준 최대) |
|---|---|---|---|
| 스토리 | 180 → 280 | 80 → 125 | 55~120 (130) |
| 드림 | 260 → 400 | 115 → 180 | 70~165 (180) |

- 설정 "탄막 밀도: 낮음/보통/높음" = ×0.6 / ×1.0 / ×1.3 (모바일 높음 ×1.15). 저장 파일이 아닌 브라우저 설정에만 저장합니다.
- 완전 자동 모드는 밀도 ×0.6, 조준탄 없음, 속도 ×0.85, 피해 ×0.75.
- 기존 탄이 많을수록 줄입니다: `RC240 탄 + 4 × 기존 탄 ≤ 최대치`.

## 피해와 공정성

- 1회 피격 피해(최대 체력 대비): 스토리 4%, 드림 8%. 피격 후 RC240 전용 무적 1.5초 / 0.9초, 심장 주변 140 / 80 px 탄 소거.
- 4초 누적 상한 18% / 30%, 체력 25% 이상에서 한 방에 죽지 않음.
- 심장 90~160 px 안에는 탄을 생성하지 않고, 생성 직후 0.12초는 판정 없음.
- 블링크 무적 중에는 통과(첫 접촉 1회만 기존 완벽 회피 판정에 전달).
- D(공명) 유지 중에는 흡수하되 회복·공명 보상은 1초에 1회만 인정(무한 회복 방지).
- 그레이즈: 심장 + 코어 + 19.4 px, 탄당 1회, 10회마다 공명 +1(10초 6 상한). 기존 RC129 그레이즈 카운터와 분리.
- 완전 자동 AI가 새 탄을 보도록 기존 위험도 함수(`LASERS.danger`)와 임박 판정(`LOOP.imminent`)에 RC240 탄을 더합니다.

## 연출 (VFX)

- 탄 그림은 실행 중 캔버스로 굽는 아틀라스: 어두운 외곽선 → 색 몸통 → 흰 코어(=판정) → 하이라이트, 발광은 별도 가산 합성 패스. 크기: 소형 점, 중형 구슬, 대형 발광구, 쌀알/바늘(진행 방향 회전), 별.
- 맵 색과 겹치지 않는 색 팔레트를 보스 계열별로 지정(용암 맵 → 청록·파랑·보라, 청록 방 → 자홍·노랑·빨강).
- 주문 중 배경을 어둡게(0.30~0.55) + 비네트, PC는 채도 낮춤. 맵 다음·탄과 캐릭터 이전에 그립니다.
- 주문 선언 배너(오른쪽에서 밀려 들어와 우상단으로 축소, 주문 이름·남은 시간·보너스), 보스 발밑 회전 마법진과 오라, 소거 시 파문처럼 번지는 불꽃, 그레이즈 불꽃, Shift 정밀 이동 시 심장 표시 고리.
- 섬광 줄이기/저사양 설정을 따르고, 섬광은 초당 1회·투명도 0.25 이하.

## 성능

- 시뮬레이션은 1000발에 약 0.04ms(노드 측정)라 무시 가능하고, 비용은 그리기에서 나옵니다. 탄 1발당 `drawImage` 1회(+발광 일부), 탄마다 save/restore·shadowBlur 없음.
- 실시간 상한: PC 640 / 모바일 260 / 저사양 200. 프레임 EWMA가 19ms를 넘으면 밀도를 0.85배씩(최저 0.35) 줄이고 안정되면 회복합니다. 기존 게임의 해상도 하향(22ms 기준)보다 먼저 반응하도록 했습니다.

## 검증 계획

- 단위 테스트: 설치 멱등성, 정지·시간정지·잠금·게스트에서 무동작, 피격 패킷 안전 플래그, 구역·주문 변경 시 소거, 성능 조절기, 패턴별 안전 통로(시드 16개 × 구간 3 × 모드 2) 시뮬레이션.
- 런타임 확장 161 매니페스트와 체인 테스트 갱신.
- 헤드리스 브라우저로 질투·발록 보스전 전후 스크린샷과 탄 수 비교(헤드리스 FPS는 소프트웨어 렌더링이라 실기 성능 근거가 아님).

## 남은 불확실성

- 체감 난이도와 밀도 수치는 첫 추정이라 실제 플레이 후 ±30% 조정이 필요할 가능성이 약 60%입니다.
- 실기기(특히 iPhone) 프레임은 측정하지 못합니다. 모바일 상한을 보수적으로 둔 이유입니다.
- 협동 게스트 화면에는 v1에서 RC240 탄이 보이지 않습니다(호스트만 시뮬레이션).

## 텍스트 관찰자 수정 (확장 163)

헤드리스 소크에서 ep1b08 보스전 진입 2~3초 뒤 페이지가 멈췄다. 원인은 1라운드 boss-form의 십자가→육망성 DOM 관찰자다.
`십자`를 담았지만 `fixText`가 바꾸지 않는 문구(ep1b08 경고 "십자 광역 · 교차선 밖으로 이동하세요")에도 `nodeValue`를 다시 써서,
같은 값을 써도 생기는 characterData 기록이 관찰자를 끝없이 다시 불렀다. 이제 바뀐 경우에만 쓴다.
검증: `tests/rc240-text-observer-unit.cjs` (수정 전 실패, 수정 후 통과), `tools/rc240c-build-extension.cjs --check`.

## 리뷰 수정 (확장 164)

리뷰 1·2차 수정(탄막·연출·모바일 담당)을 런타임 다섯 모듈에 반영했다. 2단 변신 화이트아웃은 STG feel 화면 패스의 마지막에서 그려 RC240의 모든 탄·편대·배너·HUD 위에 온다(`tests/rc240-review-order-unit.cjs`).
폰에서는 네이티브 모바일 기본값이 `reducedFlash`를 켜므로 화이트아웃 최대치가 0.2로 낮다(접근성 설정이라 바꾸지 않음).
검증: `tests/rc240-review-{danmaku,feel,mobile,order}-unit.cjs`, `tools/rc240d-build-extension.cjs --check`.

## 모달 중 카메라 고정 (확장 165)

리뷰 수정의 폰 줌 재조준 이징이 모달(대화, QA 캡처 게이트, RC233 카메라 포즈 고정)로 게임 시계가 멈춘 동안에도 진행되어, RC233 품질 브라우저의 "고정 카메라" 검사(드리프트 ≤ 1e-7)가 0.0116으로 실패했다.
모달 중 재적합은 즉시 적용하고, 진행 중이던 이징은 모달이 열리면 끝낸다. 검증: `tests/rc240-review-camera-unit.cjs`(수정 전 실패), `tests/rc233-quality-browser.cjs`(드리프트 0).

## 리뷰 2차 수정 (확장 166)

탄막·연출·카메라 담당의 2차 리뷰 수정을 런타임 다섯 모듈에 반영했다. 보스별 무기 팔레트(주인공 금색 계열과 분리), 루시퍼 깃털 창 줄, 보스 앞 편대, 편대 중 나선 중지, 탄 외곽선, 곱하기식 스펠 어둡게, 바닥 밖 탄 흐림; 하나의 연출 대기열(타이틀 → 경고 → 2형태 배너 → 스펠 카드), 전폭 타이틀 띠, 붉은 가장자리 경고, 폭탄 충격파·섬광·파편, 처치 고리; 폰 전투 줌 1.15-1.30(엔비의 방 ≤ 1.2), 바닥 모서리 화면 안 유지, 잡몹 스테이지 세로 중앙, 등각 줄무늬·셰브론 위험 띠.

## 1픽셀 크기 변화에도 줌 연속 (확장 167)

2차 수정의 프레이밍은 바닥 모서리 단계와 줌 구간 중에서 고르므로, 납작한 화면에서 뷰포트가 1픽셀만 바뀌어도 단계가 바뀌어 화면 배율이 1-4% 튀었다(RC233 품질 브라우저 844x256 → 255에서 1.07%).
2 CSS px 이하의 뷰포트 변화는 새 적합 쪽으로 화면 배율을 최대 0.9%만 옮긴다(가능한 가장 엄격한 단계에서). 더 큰 변화는 처음부터 다시 맞춘다. 검증: `tests/rc240-r2-resize-unit.cjs`(수정 전 실패), `tests/rc233-quality-browser.cjs`.
