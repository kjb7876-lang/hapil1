# RC199 combat zoom stability candidate

Base/public824c316f318344e5cf60e9157adb3e5275f4e663 is preserved. This branch is a separate un-deployed candidate. No native bundle, image, movement polygon, boss position, collision, storage, damage, narrative or orientation guide changes.

Confirmed CPU mechanism: final HAPIL_viewCameraRC104 evaluates its legacy camera, but enabled battle arenas override it through actual RC138 viewport.camera→R.camera→RC153.camera. Thus a distance-based legacy zoom is not the effective camera for these arenas. RC153's framing cache intentionally varies on living roster, actor phase/sprite, decoded images, media/EGO readiness and map-width availability. Before this change every camera call fitted the selected frame rectangle again. Alternating these keys at an unchanged window can alternate different camera scales. This reproduces a plausible mechanism for the reported web/Windows symptom; it is not a reproduction on the user's browser.

Minimal runtime change: cache the selected whole-world camera per state object, zone, real window width/height and CSS safe-area geometry. Maintain separate whole/hero/boss channels for portrait composition. Phase, actor death/spawn, active hero, image decode, map raster readiness, game/control mode, projectile population and backing DPR do not invalidate the chosen camera. Scene entry, real resize/orientation and changed safe-area geometry start a new epoch. In a VM without real window dimensions the supplied viewport is the fallback geometry. Normal resize listeners/backing-resolution behavior and portrait rotation guidance remain intact. Cache query updated to19901. Existing raw framing and actor-size calculation remain available; only whole-world camera selection is pinned.

Reproduction: run node tests/rc199-stable-combat-zoom-unit.cjs. Set RC199_LAYOUT=/tmp/rc199-before-layout.js and RC199_REPRO=1 for the archived before-version measurements. before-failing-test.log runs the same stability assertions against original bytes and fails. before-values.json and after-values.json hold exact values. Each profile runs180synthetic frames through the actual final native camera entry and actual arena delegation with actual layout/polygon. Roster, phase/sprite, decoded envelope availability, EGO decode marker, map image width, positions, legacy camera scale and DPR alternate. Paint/envelope, image readiness, native w, DOM/CSS and map-size callbacks are fixtures; no native bitmap replay or GPU.

All four traces have zero post-fix scale/x/y variation. A real window resize recalculates; current known largest fixture envelope and actual expanded legal floor remain within safe bounds. Same-window render-view jitter does not refit. Changed safe area and zone recalculate. Portrait hero/boss channels remain distinct and right-band ownership is unchanged. Existing RC195 blink/floor and RC198 mobile Cosmic geometry/anchor tests pass. These checks do not measure actual CSS resize/backing-DPR presentation or physical device orientation UI.

Limit: camera is chosen from the first available frame of each scene/viewport epoch. A later previously unseen substantially larger boss/phase/weapon is not automatically fitted by zooming out; that is the requested stability tradeoff and needs visual review for clipping. Existing paint-envelope probes include current/raised poses; this patch does not claim to pre-measure every future asset/phase. Mobile actorScale can still change intrinsic actor size through its existing policy; it no longer changes the selected world camera. Non-arena legacy cameras are unchanged. Actual user repro, candidate screenshots, all-phase art fit and monitor/DPR/DOM behavior remain unverified. No browser installation, sandbox change, Actions dispatch or new deployment is attempted.
